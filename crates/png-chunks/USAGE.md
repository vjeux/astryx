`png-chunks [--quiet] <file or directory>...` lists each PNG's chunk types and refuses the ones that carry metadata a published image must not: a `tEXt`, `iTXt`, `zTXt`, `eXIf` or `tIME` chunk, or bytes after `IEND`. A directory is walked for files whose name ends in `.png` (any case), in sorted order; a file named directly is read whatever its name. Each PNG gets one line with its chunk types in file order (a run of one type as `IDAT×7`). A failing PNG gets a second line, `  METADATA: …`, naming each chunk and its byte offset, with the keyword of a text chunk; the text itself is never printed. Other chunk types are listed, not judged. Every chunk's length, type and CRC is checked, the first chunk must be `IHDR` and an `IEND` must end the file, so a damaged or misread file is UNREADABLE, never a pass. The last line is the summary: `N PNGs: C clean, M with metadata, U unreadable`. `--quiet` prints only the failing and unreadable files and the summary. Exit 0 when every PNG is clean, 1 when a PNG carries metadata, 2 on a usage error, an unreadable file or no PNG found.
